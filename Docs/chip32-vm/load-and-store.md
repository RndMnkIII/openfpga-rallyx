| `PMPBW Rx,Ry`                                               | FPGA((Rx & 0xf0000000) \| ((Rx & 0x03ffffff) << 2)) < Ry | Z                     | Similar to PMPW but writes bytes instead. It writes bytes by left shifting the address and still writing 32 bits, but only 8 of them matter. The address written is(Rx & 0xf0000000) \| ((Rx & 0x03ffffff) << 2). This might look a little weird, but this was done so the programmer can specify a 256Mbyte space and write 64Mbyte worth of bytes here. i.e. the address range 1000_0000 to 1fff_ffff will be used for byte addressing. The code will strip off the bottom 28 bits first, leaving 1000_0000. Then, the remaining bits are left shifted twice, and OR'd back on. Bits 26/27 are ANDed off, because they would step on the upper 4 bits. Here's some address examples:<code>VM address PMP address<br>1000_0000 -&gt; 1000_0000<br>1000_0001 -&gt; 1000_0004<br>1000_0002 -&gt; 1000_0008<br>1000_0003 -&gt; 1000_000C<br>1000_0004 -&gt; 1000_0010<br>1000_1234 -&gt; 1000_48D0<br>13ff_ffff -&gt; 1fff_fffc<br>1400_0000 -&gt; 1000_0000 // we AND off bits 26 and 27, so the address &quot;wraps around&quot; to 1000_0000 again.<br>1800_0001 -&gt; 1000_0004 // we wrap again due to bits 26/27 being ANDed<br>1c00_0002 -&gt; 1000_0008 // and this also wraps too.<br>1fff_ffff -&gt; 1fff_fffc // and wrap again!</code>On the FPGA, these addresses can just be aliased to another range to perform the byte writes if you need to write to RAM byte-wise for some reason, vs. word wise like usual. |
